# C-Monitor 3차(나머지 전부) 구현 계획

**Goal:** 설계 문서와 목업에 있었지만 1·2차에서 빠진 기능을 모두 만든다.

**Spec:** `docs/superpowers/specs/2026-11-14-c-monitor-design.md` 3·6·8·9절, 목업 `docs/mockup/canvas/Admin.dc.html`·`Main.dc.html`.

텔레그램 알림(세션별 스위치, 관리자 화면의 봇 토큰 포함)은 별도 웨이브로 먼저 끝낸다. 이 계획은 그 뒤의 나머지다.

## Global Constraints

- 1·2차 계획의 제약을 그대로 따른다(한글 합니다체, 디자인 토큰, 사용자별 격리, 비밀 커밋 금지, 플러그인 의존성 0).
- **저장소에는 실제 이메일·내부 호스트명·IP·운영 주소를 넣지 않는다.**
- 설정할 값은 모두 웹 화면에서 바꾼다. 운영자가 스크립트를 돌리거나 환경변수를 고칠 일을 새로 만들지 않는다(꼭 필요한 비밀 키는 서버가 처음 뜰 때 스스로 만들어 DB에 둔다).
- 에이전트는 git 기록을 바꾸지 않는다. 커밋·배포는 조정자만 한다.

## 기능 목록과 결정

| # | 기능 | 결정 |
|---|---|---|
| 2 | 웹 알림(Web Push) | 표준 Web Push(VAPID). VAPID 키는 서버가 처음 뜰 때 만들어 DB에 저장. 서비스 워커 `web/public/sw.js`. 사용자 설정 › 알림에서 "이 브라우저에서 받기"(브라우저마다 구독, 여러 개 가능). 항목은 텔레그램과 같은 설정(wait/done/lost/limit)과 세션별 스위치를 함께 따른다(세션 스위치는 "알림" 전체 — 텔레그램·웹 둘 다). 알림을 누르면 그 세션 상세가 열린다. 의존성: 서버 `web-push` 패키지 사용 가능 |
| 3 | 웹 알림 소리 | 브라우저마다(localStorage) 켜기·끄기. 대시보드가 열려 있을 때 세션이 wait/done이 되면 짧은 소리(Web Audio로 합성, 파일 없음) |
| 4 | 링크 공유 | 세션 상세 › 공유: 링크 만들기(만료: 1시간/1일/7일/없음), 목록·취소. `/s/<토큰>`은 로그인 없이 그 세션의 상태·대화를 **보기만**(실시간 갱신 포함, 답장·원격 제어·컴퓨터 정보 없음). 토큰은 해시로 저장 |
| 5 | 사람 지정 공유 | 같은 공유 창에서 가입 사용자 이메일로 지정. 받은 사람 대시보드에 "공유받은 세션" 묶음(`sharedBy` 표시), 보기만. 기존 `shares` 표 사용 |
| 6 | 탈퇴 | 내 설정 › 계정 › 탈퇴: 즉시 로그인·전송 차단(기기 토큰 무효), 7일 뒤 완전 삭제. 7일 안에 다시 로그인하면 "탈퇴 취소" 화면. 관리자 화면에 "삭제 예정" 표시와 즉시 삭제·복구 |
| 7 | 가입 고지·동의 | 가입(첫 로그인) 화면에 "관리자는 서비스 운영을 위해 모든 대화를 볼 수 있습니다" + 비밀 가림 설명 + 동의 체크. 동의해야 신청된다. 동의 시각 저장 |
| 8 | 저장 용량 한도 | 사용자당 기본 1GB(관리자가 사용자별로 바꿈, 0=무제한). 매일 정리 때 넘으면 오래된 대화 줄부터 지우고 텔레그램·웹 알림 + 설정 화면 안내 |
| 9 | 저장 용량 표시 | 관리 › 저장 용량: 전체·대화·사용량·기타, 디스크 남은 공간, 사용자별 사용량. 내 설정에도 내 사용량/한도 |
| 10 | 관리자: 남의 대시보드 보기 | 관리 › 사용자 목록에서 "대시보드 보기" → `?user=<id>`로 그 사용자의 대시보드(읽기 전용 띠 표시, 답장·삭제 불가) |
| 11 | 관리자: 모든 컴퓨터 | 관리 › 컴퓨터: 모든 사용자의 컴퓨터(소유자, 운영체제, 플러그인, 마지막 전송, 원격 답장 스위치) + 연결 해제 |
| 12 | 관리자: Gmail 미리 추가 | 관리 › 사용자 › 추가: 이메일을 넣으면 그 사람은 첫 로그인 때 승인 없이 바로 사용(동의는 받음). 권한(관리자/사용자) 선택 |
| 13 | 기록 탭 | 대시보드 상단 "기록" 탭: 종료 뒤 기준 시간이 지난 세션 목록(검색·컴퓨터 필터·삭제), 누르면 상세(읽기 전용) |
| 14 | 컨텍스트 %·비용 | 상태줄 입력의 `context_window`(사용 %)와 `cost.total_cost_usd`를 세션별로 보낸다(상태줄 래퍼, 60초에 한 번 → 세션별 값은 바뀔 때만). 상세 패널·카드에 표시 |
| 15 | 웹 답 기록 줄 | 웹·텔레그램에서 답하면 그 세션 대화에 시스템 줄 "웹에서 「허용」으로 답했습니다"(텔레그램이면 "텔레그램에서") 추가 |
| 16 | 보관 0 = 지우지 않음 | 대화·사용량 보관 기간 0 허용 |
| 17 | 목업 반영 | 아티팩트 목업에 여러 사람용 화면(가입·승인 대기·관리·공유·기록) 반영 |
| 18 | 글 전달 수신 확인 | inbox 응답의 글을 플러그인이 stderr에 쓴 뒤 `POST /api/reply/inbox/ack {id}`. 서버는 ack가 오기 전에는 같은 글을 다음 대기자에게 다시 준다(60초 뒤). ack 뒤에 본문 삭제 |

## Review Focus

1. 공유 링크로 남의 세션 대화가 보일 때 컴퓨터·다른 세션·답장 경로가 하나도 새지 않는다.
2. 탈퇴한 사용자의 기기 토큰·로그인·공유 링크가 즉시 막힌다.
3. 용량 정리가 최신 대화를 지우지 않고, 한도 0이면 아무것도 지우지 않는다.
4. 웹 푸시 구독이 만료(410)되면 지우고, 남의 세션 알림이 가지 않는다.
5. 관리자가 남의 대시보드를 볼 때 답장·삭제·설정 변경이 서버에서 막힌다.
