# C-Monitor 1차(핵심) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 플러그인이 보낸 세션 이벤트를 서버가 사용자별로 저장하고, 웹 대시보드(상세·간단히)가 실시간으로 보여 주며, 구글 로그인·가입 승인·기기 연결까지 되는 상태로 server-a에 배포한다.

**Architecture:** npm 워크스페이스 모노레포. `shared/`에 API 계약(타입·zod 스키마)과 상태 규칙을 두고 서버·웹·플러그인이 같은 계약을 따른다. 서버는 Hono + Postgres, 실시간은 SSE. 플러그인은 의존성 없는 Node ESM 스크립트.

**Tech Stack:** Node 24, TypeScript 5, Hono 4, `postgres` 3, zod 3, Vite 6 + React 18, vitest 2, Docker(arm64).

**Spec:** `docs/superpowers/specs/2026-11-14-c-monitor-design.md`

**범위 밖:** 원격 답장(2차 계획), 텔레그램·웹 푸시·공유·용량 한도·탈퇴 삭제·약관·관리자 확장(3차 계획). 데이터 모델은 처음부터 사용자 소유·공유를 견디게 만든다.

## Global Constraints

- 화면 문구는 한글 합니다체, 버튼은 명사형("저장", "연결 승인").
- 디자인 토큰은 `web/src/styles/app.css`·`deck.css`만 사용(7 Quartz). 목업 원본은 `docs/mockup/*.dc.html`.
- 플러그인은 런타임 의존성 0개, Node 18 이상, Windows·Linux 경로 모두 지원.
- 훅은 클로드코드를 막지 않는다: `async: true`, 네트워크 제한시간 3000ms, 예외는 삼키고 디스크 큐에 보관.
- 모든 조회·스트림은 `user_id`로 거른다. 관리자(`role='admin'`)만 전체 열람.
- 비밀은 커밋 금지. 저장소는 공개.
- 서버 포트 3000. 환경변수 `DATABASE_URL`, `PUBLIC_URL`, `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SESSION_SECRET`, `ADMIN_EMAILS`.
- 기본값: 끊김 10분, 종료 카드 유지 24시간, 대화 보관 30일, 사용량 보관 90일.

## Review Focus

1. 서버가 꺼져 있을 때 — 훅은 3초 안에 끝나고, 이벤트는 큐에 남았다가 다음 전송 때 순서대로 나간다. (Task P2 테스트)
2. 남의 데이터 — 사용자 A의 기기 토큰·로그인으로 B의 세션·대화·스트림 이벤트가 절대 보이지 않는다. (Task S3·S4 테스트)
3. Windows 경로·CRLF — `C:\...\x.jsonl`, CRLF 줄끝, 마지막 줄이 덜 써진 JSONL에서도 증분 읽기가 깨지지 않는다. (Task P1 테스트)
4. 큰 대화 — 한 줄 64KB 초과는 잘라서 `truncated:true`, 한 번 전송 최대 512KB로 나눠 보낸다. (Task P1·S3 테스트)
5. SSE 재연결 — 끊겼다 다시 붙으면 클라이언트가 스냅샷을 다시 받아 빠진 상태가 없다. (Task W1 테스트)

## Wave 0 — 계약과 뼈대 (오케스트레이터가 직접)

### Task C1: 워크스페이스·공용 계약·상태 규칙

**Files:** Create `package.json`, `tsconfig.base.json`, `shared/package.json`, `shared/src/{contract,status,index}.ts`, `shared/test/status.test.ts`

**Interfaces — Produces:**
- `IngestBatch` = `{ machine: MachineInfo, events: HookEvent[], transcript: TranscriptChunk[], limits?: LimitSnapshot }` 및 같은 이름의 zod 스키마 `IngestBatchSchema`
- `HookEvent` = `{ id: string(uuid), sessionId, event: HookEventName, at: string(ISO), account: string|null, cwd, branch: string|null, model: string|null, data: Record<string,unknown> }`
- `TranscriptChunk` = `{ sessionId, seq: number, lines: TranscriptLine[] }`, `TranscriptLine` = `{ role: 'user'|'assistant'|'tool'|'system', at, text, toolName?, toolInput?, truncated?: boolean, masked?: number }`
- `LimitSnapshot` = `{ account: string, fiveHourPct, fiveHourResetsAt: number|null, sevenDayPct, sevenDayResetsAt: number|null, at }`
- `SessionStatus` = `'run'|'wait'|'done'|'lost'|'end'|'limit'`
- `nextStatus(prev: SessionStatus|null, e: Pick<HookEvent,'event'|'data'>): SessionStatus`
- `isLost(status, lastEventAt: Date, now: Date, lostMinutes: number): boolean`
- `SessionView`, `AccountView`, `MachineView`, `StreamMessage` = `{ type: 'snapshot'|'session'|'log'|'limits'|'machine', ... }`
- 경로 상수 `API` = `{ ingest:'/api/ingest', deviceStart:'/api/device/start', devicePoll:'/api/device/poll', deviceApprove:'/api/device/approve', me:'/api/me', sessions:'/api/sessions', stream:'/api/stream' }`

- [ ] 상태 규칙 실패 테스트 작성: `nextStatus(null,{event:'UserPromptSubmit'})==='run'`, Notification `permission_prompt`→`wait`, `idle_prompt`는 이전 상태 유지, PreToolUse `AskUserQuestion`→`wait`, Stop→`done`, StopFailure `rate_limit`→`limit`, SessionEnd→`end`, `isLost('run', t, t+11분, 10)===true`, `isLost('wait', …)===false`
- [ ] `npx vitest run shared` 실패 확인 → 구현 → 통과 확인 → 커밋 `feat(shared): API 계약과 상태 규칙`
