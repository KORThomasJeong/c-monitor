# 구글 로그인(OAuth) 설정

C-Monitor 대시보드는 구글 계정으로만 로그인합니다. 서버를 직접 올렸다면 구글 클라우드 콘솔에서 **로그인용 클라이언트**를 하나 만들고, 그 값(클라이언트 ID와 보안 비밀)을 서버에 넣어야 로그인이 됩니다. 한 번만 하면 됩니다.

걸리는 시간은 10분쯤이고 비용은 들지 않습니다. C-Monitor가 구글에 요청하는 정보는 **이메일 주소와 이름**뿐이라, 구글의 앱 심사도 필요하지 않습니다.

> 구글 클라우드 콘솔의 메뉴 이름과 배치는 구글이 가끔 바꿉니다. 아래 이름과 다르게 보이면 뜻이 같은 메뉴를 찾으면 됩니다. 예전 화면에서는 "API 및 서비스 › OAuth 동의 화면", "API 및 서비스 › 사용자 인증 정보"였습니다.

## 준비물

- 서버가 이미 떠 있고 주소가 정해져 있어야 합니다. 서버의 `deploy/.env.prod`에 `PUBLIC_URL`(예: `https://c-monitor.example.com`)이 들어 있어야 합니다. ([직접 서버에 올리기](self-hosting.md) 참고)
- 구글 계정 하나.
- **리디렉션 주소**: `PUBLIC_URL` 뒤에 `/auth/google/callback`을 붙인 것입니다. 예: `https://c-monitor.example.com/auth/google/callback`. 이 문자열을 구글 콘솔에 한 글자도 다르지 않게 넣어야 합니다.

## 방법 1: 안내 스크립트로 하기 (권장)

저장소를 받아 둔 PC에서 아래를 실행합니다. `<SSH 대상>`은 `ssh <SSH 대상>`으로 서버에 접속할 때 쓰는 이름입니다.

```bash
bash deploy/setup-google-oauth.sh <SSH 대상>
# 서버에서 저장소 폴더 이름이 c-monitor가 아니면 두 번째 인자로 줍니다
bash deploy/setup-google-oauth.sh <SSH 대상> my-folder
```

스크립트가 다섯 단계로 안내합니다.

1. 서버에 접속해 사이트 주소를 읽고, 구글 콘솔에 넣을 리디렉션 주소를 보여 줍니다.
2. 구글 클라우드 콘솔을 열어 줍니다. 프로젝트를 고르거나 새로 만듭니다.
3. 로그인 동의 화면 설정 페이지를 열어 줍니다. 무엇을 입력할지 화면에 나옵니다.
4. 클라이언트 만들기 페이지를 열어 줍니다. 만든 뒤 클라이언트 ID와 보안 비밀을 붙여 넣습니다.
5. 값을 서버의 `deploy/.env.prod`에 넣고 앱을 다시 띄운 뒤, 로그인 주소가 새 값으로 바뀌었는지 확인합니다.

알아 둘 점은 다음과 같습니다.

- 보안 비밀은 입력할 때 화면에 보이지 않고, 이 PC에는 저장되지 않습니다. 서버로는 SSH 표준입력으로만 전달됩니다.
- 바꾸기 전의 `deploy/.env.prod`는 같은 폴더에 `.env.prod.bak`으로 남습니다.
- 앱을 다시 띄워도 이미 로그인돼 있던 사람은 그대로 유지됩니다.
- Windows에서는 Git Bash에서 실행합니다. 서버의 로그인 셸은 bash여야 합니다.

## 방법 2: 손으로 하기

### 1. 프로젝트 고르기

[구글 클라우드 콘솔](https://console.cloud.google.com/)에 로그인합니다. 화면 맨 위 프로젝트 선택 칸에서 쓸 프로젝트를 고르거나 "새 프로젝트"로 하나 만듭니다(이름 예: `c-monitor`).

### 2. 로그인 동의 화면 만들기

왼쪽 메뉴에서 **Google 인증 플랫폼**(Google Auth Platform)으로 갑니다. 처음이면 "시작하기"가 보입니다.

| 항목 | 넣을 값 |
|---|---|
| 앱 이름 | `C-Monitor` (구글 로그인 창에 보이는 이름) |
| 사용자 지원 이메일 | 본인 주소 |
| 대상 | **외부** — 일반 Gmail로 로그인하려면 외부여야 합니다. "내부"는 구글 워크스페이스 조직 안에서만 로그인할 때 고릅니다 |
| 연락처 이메일 | 본인 주소 |

정책 동의에 체크하고 만듭니다.

이어서 왼쪽 **대상** 메뉴에서 게시 상태를 정합니다.

- **테스트**: "테스트 사용자"에 추가한 구글 계정만 로그인할 수 있습니다(최대 100명). 쓰는 사람이 몇 명뿐이면 이 상태로 충분합니다. 로그인할 Gmail 주소를 모두 추가해 두세요.
- **프로덕션으로 게시**: 구글 계정이 있는 누구나 구글 로그인 창까지는 지나갈 수 있습니다. 가입 신청을 넓게 받으려면 게시합니다.

어느 쪽이든 C-Monitor 안에서는 **관리자가 승인한 사람만** 쓸 수 있습니다. 구글 쪽 설정은 "구글 로그인 창을 통과할 수 있는 사람"을 정할 뿐입니다.

### 3. 클라이언트 만들기

왼쪽 **클라이언트** 메뉴에서 "클라이언트 만들기"를 누릅니다.

| 항목 | 넣을 값 |
|---|---|
| 애플리케이션 유형 | **웹 애플리케이션** |
| 이름 | `c-monitor` (콘솔에서 구분하는 이름) |
| 승인된 자바스크립트 원본 | 비워 둡니다 |
| 승인된 리디렉션 URI | `PUBLIC_URL` + `/auth/google/callback` |

"만들기"를 누르면 **클라이언트 ID**(`….apps.googleusercontent.com`으로 끝남)와 **클라이언트 보안 비밀**이 표시됩니다. 보안 비밀은 이 창을 닫으면 다시 전체를 볼 수 없으니 이때 복사해 둡니다. 놓쳤다면 클라이언트 상세 화면에서 보안 비밀을 새로 추가하면 됩니다.

### 4. 서버에 넣기

서버의 `deploy/.env.prod`에서 두 줄을 채웁니다.

```
GOOGLE_CLIENT_ID=<클라이언트 ID>
GOOGLE_CLIENT_SECRET=<클라이언트 보안 비밀>
```

그리고 앱을 다시 띄웁니다.

```bash
docker compose -f deploy/compose.yml --env-file deploy/.env.prod up -d
```

### 5. 확인

브라우저에서 `PUBLIC_URL/login`을 열고 "Gmail 계정으로 로그인"을 누릅니다. `ADMIN_EMAILS`에 적어 둔 주소로 로그인하면 바로 대시보드가 열리고, 그 밖의 주소는 "가입 신청을 받았습니다" 화면이 나옵니다.

## 자주 나는 오류

| 화면에 나오는 것 | 원인과 해결 |
|---|---|
| `redirect_uri_mismatch` | 콘솔에 넣은 리디렉션 주소가 서버 주소와 다릅니다. `https`인지, 끝에 `/`가 붙지 않았는지, `/auth/google/callback`까지 정확한지 확인합니다. 서버의 `PUBLIC_URL`도 실제 접속 주소와 같아야 합니다 |
| "액세스 차단됨" 또는 `access_denied` | 동의 화면이 "테스트" 상태인데 그 구글 계정이 테스트 사용자에 없습니다. 테스트 사용자에 추가하거나 앱을 게시합니다 |
| `invalid_client` | 클라이언트 ID나 보안 비밀이 잘못 들어갔습니다. 앞뒤 공백이 섞이지 않았는지 확인하고 다시 넣습니다 |
| 로그인 뒤 다시 로그인 화면으로 돌아옴 | `PUBLIC_URL`이 `https`인데 실제로는 `http`로 접속하고 있을 수 있습니다. 로그인 쿠키는 `https`에서만 전달됩니다 |
| 로그인은 됐는데 "가입 신청을 받았습니다"만 나옴 | 정상입니다. 관리자 계정으로 로그인해 관리자 화면에서 승인하면 됩니다. 본인이 관리자여야 한다면 그 주소가 서버의 `ADMIN_EMAILS`에 있는지 확인합니다 |

## 값이 저장되는 곳

- 클라이언트 ID와 보안 비밀은 **서버의 `deploy/.env.prod`에만** 있습니다. 이 파일은 저장소에 커밋되지 않습니다.
- C-Monitor는 구글에서 이메일 주소와 이름만 받아 사용자 구분에 씁니다. 구글 계정의 다른 정보(메일, 드라이브 등)에는 접근하지 않고, 구글이 준 토큰도 저장하지 않습니다.
