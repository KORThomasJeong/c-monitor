# 플러그인

C-Monitor 플러그인은 클로드코드의 훅과 상태줄을 이용해 세션 정보를 서버로 보내고, 웹에서 보낸 답을 세션에 넘깁니다. 의존성 없는 Node 스크립트로 되어 있고 Node 18 이상이 필요합니다. 지금 버전은 **0.3.1**입니다. 이 문서는 플러그인이 무엇을 보내고 무엇을 보내지 않는지, 원격 답장이 어떻게 동작하는지, 서버가 꺼졌을 때 어떻게 되는지, 이 컴퓨터에 무엇을 남기는지를 정리합니다. 코드는 [`plugin/`](../../plugin/)에 있습니다.

| 버전 | 들어온 것 |
|---|---|
| 0.2.0 | 원격 답장(웹에서 승인·선택지·글), 원격 제어 링크 |
| 0.3.0 | 세션별 컨텍스트 사용률·비용 전송, 웹에서 보낸 글의 수신 확인 |
| 0.3.1 | 클로드코드가 스스로 넣은 사용자 줄(훅 결과·백그라운드 작업 알림)을 사람이 쓴 글로 보내지 않고, 웹에서 보낸 글이 대화에 내부 형식 그대로 보이던 것을 고침 |

## 구성

| 부분 | 하는 일 |
|---|---|
| 훅 (`bin/hook.mjs`) | 세션 시작·종료, 질문 입력, 도구 실행 전후, 알림, 작업 끝남 등 10가지 훅 이벤트마다 실행되어 이벤트와 늘어난 대화를 보냅니다 |
| 승인 훅 (`bin/ask.mjs`) | 승인 창·선택지 질문이 뜰 때(`PermissionRequest`) 서버에 요청을 올리고, 웹에서 답이 오면 그 답을 클로드코드에 돌려줍니다 |
| 글 받기 훅 (`bin/inbox.mjs`) | 작업이 끝나거나 세션이 시작될 때(`Stop`·`SessionStart`) 뒤에서 기다리다가, 웹에서 글이 오면 멈춘 세션을 깨워 넘깁니다 |
| 연결 명령 (`/c-monitor:connect`, `bin/connect.mjs`) | 서버 연결(`--start`로 요청하고 링크·코드 출력 → `--wait`로 승인 기다림), 연결 상태 확인(`--status`), 연결 해제(`--disconnect`) |
| 상태줄 래퍼 (`bin/statusline.mjs`) | 상태줄 입력에서 5시간·주간 한도와 세션별 컨텍스트 사용률·비용을 읽어 보내고, 원래 상태줄 명령을 그대로 실행합니다 |

현황을 보내는 훅은 `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `PostToolUseFailure`, `Notification`, `Stop`, `StopFailure`, `SubagentStop`, `SessionEnd`에 걸립니다. 모두 비동기 훅(`async: true`)이라 클로드코드는 훅이 끝나기를 기다리지 않습니다. 원격 답장용 `PermissionRequest` 훅만 동기 훅이지만, 터미널의 승인 창과 함께 떠 있으므로 입력을 막지 않습니다([원격 답장](#원격-답장)).

## 무엇을 보내나요

> **대화 전체가 서버로 전송되어 저장됩니다.** 사용자가 쓴 글, 클로드의 답, 도구 입력과 결과(명령 출력, 읽은 파일 내용 등)가 모두 포함됩니다. 비밀처럼 보이는 글자는 가려서 보내지만 모양으로 찾는 방식이라 완벽하지 않습니다. 저장된 대화는 서버 관리자가 운영을 위해 볼 수 있습니다([자주 묻는 질문](faq.md)).

| 종류 | 내용 | 언제 |
|---|---|---|
| 훅 이벤트 | 이벤트 이름과 시각, 클로드 세션 ID, 클로드 계정 이메일, 작업 폴더 경로, 깃 브랜치, 모델, 그리고 이벤트별 필드(아래) | 훅마다 |
| 대화 | 세션 대화 기록(transcript)에서 지난번 이후 늘어난 줄. 사용자 글, 클로드 글, 도구 호출(도구 이름과 입력), 도구 결과 | 훅마다 |
| 한도 | 클로드 계정 이메일, 5시간·주간 사용률과 초기화 시각 | 상태줄이 그려질 때, 계정마다 60초에 한 번까지 |
| 컨텍스트·비용 | 세션별 컨텍스트 사용률(%)과 누적 비용(USD, `cost.total_cost_usd`) | 상태줄이 그려질 때 값이 바뀌었으면, 세션마다 60초에 한 번까지(0.3.0부터) |
| 원격 답장 | 승인·질문이 뜰 때의 요청 내용, 원격 제어 주소 | [원격 답장](#원격-답장) 참고 |
| 컴퓨터 | 컴퓨터 이름, 운영체제와 버전, 플러그인 버전 | 매 전송에 함께 |

훅 이벤트에 담는 필드는 정해져 있습니다: `prompt`, `tool_name`, `tool_input`, `tool_use_id`, `notification_type`, `message`, `title`, `last_assistant_message`, `error`, `error_details`, `is_interrupt`, `reason`, `source`, `stop_hook_active`, `permission_mode`, `agent_id`, `agent_type`. 이 가운데 4000자가 넘는 글은 자르고, 8KB가 넘는 도구 입력은 앞부분 미리보기만 보냅니다. 도구 실행 결과(`tool_response`)는 훅 이벤트로는 보내지 않고 대화 기록 쪽으로 갑니다.

몇 가지 세부 사항입니다.

- **클로드 계정**은 매 이벤트마다 `~/.claude.json`(또는 `$CLAUDE_CONFIG_DIR/.claude.json`)의 `oauthAccount.emailAddress` 값만 읽습니다. 계정을 바꾸면 다음 이벤트부터 바뀐 계정으로 잡힙니다.
- **깃 브랜치**는 작업 폴더에서 위로 올라가며 `.git/HEAD` 파일을 읽어 알아냅니다. 깃 명령을 실행하지 않습니다. 브랜치가 아니면 짧은 커밋 해시를 보냅니다.
- **컴퓨터 이름**은 연결할 때의 호스트 이름입니다.
- **연결하기 전부터 열려 있던 세션**은 연결 뒤 첫 훅에서 그 세션의 대화 기록을 처음부터 읽어 보냅니다. 그 뒤로는 늘어난 만큼만 보냅니다.
- 대화 한 줄은 64KB, 도구 입력은 32KB가 넘으면 잘라서 보내고 "일부 생략" 표시를 붙입니다. 한 번에 보내는 묶음은 512KB를 넘지 않게 나눕니다.
- 클로드코드가 스스로 넣은 사용자 줄(훅 결과, 백그라운드 작업 알림 등)은 사용자 글이 아니라 짧게 요약한 시스템 줄로 보냅니다. 웹에서 보낸 글로 세션을 깨운 줄은 그 글만 사용자 글로 보냅니다(0.3.1부터).

## 보내지 않는 것

- 클로드의 생각 과정(thinking 블록)
- 메시지 안의 이미지(도구 결과 속 이미지는 `[이미지]`라는 글자로만 남깁니다)
- 서브에이전트 안쪽 대화, 메타 항목, 첨부 항목 등 사용자와 클로드의 대화가 아닌 기록
- 대화 기록 밖의 파일. 플러그인이 직접 읽는 파일은 대화 기록, `~/.claude.json`의 계정 이메일, `.git/HEAD`, 그리고 자기 설정 파일뿐입니다. 다만 클로드가 도구로 읽은 파일 내용은 대화 기록의 도구 결과에 들어 있으므로 함께 전송됩니다.

## 비밀 가림

보내기 전에 이 컴퓨터에서 비밀처럼 보이는 글자를 `••••••••`로 바꿉니다. 대화 줄, 도구 입력, 훅 이벤트 필드 모두에 적용되고, 가린 개수를 함께 보내 상세 화면에 "키 N개 가려짐"으로 표시합니다. 원래 값은 서버로 가지 않습니다. 규칙은 [`plugin/lib/mask.mjs`](../../plugin/lib/mask.mjs)에 있습니다.

| 종류 | 찾는 모양 | 가리는 범위 |
|---|---|---|
| 개인 키 | `-----BEGIN … PRIVATE KEY-----`부터 `-----END … PRIVATE KEY-----`까지 | 블록 전체 |
| 이름=값 | `password=`, `passwd=`, `secret=`, `token=`, `api_key=`, `apikey=` (대소문자 무관, `DB_PASSWORD=`·`SEARCH_API_KEY=`처럼 밑줄 등으로 이어진 접두어 포함) | `=` 뒤의 값 |
| Bearer 토큰 | `Bearer ` 뒤 8자 이상 | `Bearer ` 뒤의 값 |
| JWT | `eyJ`로 시작하고 점으로 나뉜 세 부분 | 전체 |
| `sk-` 키 | `sk-` 뒤 20자 이상(`sk-ant-…` 포함) | 전체 |
| GitHub 토큰 | `ghp_`·`gho_`·`ghu_`·`ghs_`·`ghr_` 뒤 20자 이상, `github_pat_…` | 전체 |
| AWS 액세스 키 ID | `AKIA` + 16자 | 전체 |
| Slack 토큰 | `xoxb-`·`xoxp-` 뒤 10자 이상 | 전체 |
| Google API 키 | `AIza` + 35자 | 전체 |
| Google OAuth 클라이언트 보안 비밀 | `GOCSPX-` + 20자 이상 | 전체 |
| Google OAuth 액세스 토큰 | `ya29.` + 20자 이상 | 전체 |
| 도구 입력의 비밀 이름 | 도구 입력 객체에서 키 이름이 `password`·`passwd`·`secret`·`token`·`api_key`·`api-key`·`apikey`인 값 | 값 전체(모양과 상관없이) |

모양으로 찾는 방식이라 빠지는 것이 있습니다. 예를 들어 `password: abc`처럼 `=` 대신 콜론을 쓴 글, `MYPASSWORD=`처럼 이름 앞에 글자가 바로 붙은 경우, 데이터베이스 주소 안의 비밀번호(`postgres://user:비밀번호@…`), AWS 비밀 액세스 키, 정해진 앞글자가 없는 일반 토큰은 가려지지 않습니다. 비밀을 화면에 출력하거나 대화에 붙여 넣지 않는 것이 가장 안전합니다.

## 원격 답장

웹 대시보드와 텔레그램에서 이 컴퓨터의 세션에 답할 수 있게 합니다. 화면에서 하는 일은 [원격 답장](remote-reply.md)에 있고, 여기서는 플러그인 쪽 동작을 적습니다.

- **승인·질문**: 승인 창이나 선택지 질문이 뜨면 `PermissionRequest` 훅(`bin/ask.mjs`)이 서버에 요청을 등록합니다. 3초 안에 등록하지 못하면 포기하고 아무것도 출력하지 않은 채 끝나므로 터미널 창은 평소처럼 동작합니다. 등록한 뒤에는 웹의 답이 올 때까지 서버에 되풀이해 묻고, 답이 오면 그 결정(허용·이 세션 동안 허용·거부, 또는 질문의 답)을 클로드코드에 돌려줍니다. 터미널에서 먼저 답하면 서버가 알려 주어 스스로 끝납니다.
- **글**: 작업이 끝나거나 세션이 시작될 때 `Stop`·`SessionStart` 훅(`bin/inbox.mjs`)이 뒤에서 조용히 기다립니다(25초쯤에 한 번 서버에 물음). 웹에서 글이 오면 그 글을 세션에 넘겨 깨우고, 서버에 수신 확인(세션 id와 글 id)을 보냅니다. 서버는 수신 확인을 받으면 글 본문을 지우고, 확인이 오지 않으면 60초 뒤 같은 글을 다음 대기자에게 다시 줍니다(0.3.0부터). 세션마다 기다리는 프로세스가 하나 떠 있고, 클로드코드가 끝나면 같이 끝납니다.
- **원격 제어**: 세션에서 `/remote-control`을 켜면 클로드코드가 훅 환경에 원격 제어 세션 값을 넣어 줍니다. 플러그인은 그 값으로 만든 공식 화면 주소(`https://claude.ai/code/…`)를 훅 이벤트에 함께 보냅니다.
- 승인 창이 뜨지 않는 권한 모드(자동 승인·승인 건너뛰기)에서는 `PermissionRequest` 자체가 없으므로 아무것도 올리지 않습니다.

원격 답장 때문에 서버로 더 보내는 것:

| 언제 | 내용 |
|---|---|
| 승인 창이 뜰 때 | 세션 id, 도구 이름, 도구 입력(비밀을 가리고 큰 입력은 앞부분만), 서브에이전트 id, "이 세션 동안 허용"이 하는 일을 설명한 한 줄 |
| 선택지 질문이 뜰 때 | 위와 같고, 질문 글과 선택지(비밀 가림) |
| 훅 이벤트마다 | 원격 제어를 켠 세션이면 그 화면 주소 |

**끄는 방법**: 웹의 **설정 › 내 컴퓨터**에서 그 컴퓨터의 **원격 답장** 스위치를 끕니다(기본은 켜짐). 끄면 서버가 승인·질문 등록을 저장하지 않고 "꺼져 있음"으로 돌려주므로 승인 훅은 바로 물러나고, 글 받기 훅도 조용히 끝납니다. 세션 현황을 보내는 것은 그대로입니다.

## 서버가 꺼졌을 때

- 훅은 보낼 내용을 먼저 디스크 큐(`~/.c-monitor/queue/`)에 넣은 뒤 보냅니다. 요청마다 3초 제한이 있고, 훅 프로세스는 늦어도 3.6초 안에 끝납니다. 훅은 화면에 아무것도 출력하지 않고 항상 정상 종료합니다.
- 보내지 못한 묶음은 큐에 남았다가 다음 훅이 실행될 때 넣은 순서대로 다시 보냅니다. 앞의 묶음이 실패하면 거기서 멈춰 순서를 지킵니다. 다시 보내는 때는 다음 훅 이벤트가 생길 때이므로, 세션 활동이 없으면 큐도 그대로 기다립니다.
- 큐는 200묶음까지 두고, 넘치면 오래된 것부터 버립니다.
- 서버가 모양이 틀렸다고 거절한 묶음(400·413·422)은 다시 보내도 같으므로 버립니다. 서버 꺼짐, 사용자 정지(403), 서버 오류(5xx)는 큐에 남깁니다.
- 서버가 401을 돌려주면 웹에서 이 컴퓨터의 연결을 해제한 것으로 봅니다. 설정 파일에 해제 표시를 남기고 큐를 비운 뒤, 그 뒤로는 훅과 상태줄 래퍼 모두 아무것도 쌓거나 보내지 않습니다. `/c-monitor:connect`(인자 없이 또는 `--status`)를 실행하면 "○ 서버에서 연결이 해제되었습니다. 이 컴퓨터의 세션은 전송되지 않습니다."라고 알려 주고, 연결 명령을 다시 실행하면 해제 표시가 사라지고 전송이 이어집니다.
- 한도 전송은 2초 제한으로 한 번만 시도하고, 실패하면 큐에 넣지 않고 넘어갑니다. 60초가 지난 뒤 상태줄이 다시 그려질 때 새 값을 보냅니다.
- 서버가 컨텍스트·비용 필드를 모르는 옛 버전이라 거절(400)하면, 그 뒤 24시간은 컨텍스트·비용을 빼고 한도만 보냅니다.
- 원격 답장의 승인 훅은 서버에 닿지 않으면 3초 안에 물러나 터미널에 맡깁니다. 글 받기 훅은 서버가 꺼져 있는 동안 조용히 다시 묻기만 합니다.

남은 묶음 수는 `/c-monitor:connect`(인자 없이)의 "보낼 묶음"에서 봅니다.

## 상태줄 래퍼

5시간·주간 한도와 컨텍스트 사용률(`context_window`)·비용(`cost`)은 클로드코드가 상태줄 명령에 넘기는 입력에만 들어 있습니다. 그래서 연결 명령은 `~/.claude/settings.json`(또는 `$CLAUDE_CONFIG_DIR/settings.json`)의 `statusLine`을 플러그인의 래퍼로 바꿉니다.

- 래퍼 파일은 `~/.c-monitor/bin/statusline.mjs`로 복사되고, `statusLine`은 `node "<그 경로>"` 명령이 됩니다.
- 바꾸기 전의 `statusLine` 값은 `~/.c-monitor/config.json`에 기억하고, 고치기 전 `settings.json`은 `settings.json.c-monitor.bak`으로 남깁니다. `settings.json`의 다른 설정은 건드리지 않습니다.
- 래퍼는 원래 상태줄 명령을 같은 입력으로 실행하고 그 출력을 그대로 보여 줍니다. 기존에 쓰던 상태줄(claude-hud 등)은 그대로 보입니다. 한도 전송은 원래 명령 실행과 동시에 진행되어 상태줄 출력을 늦추지 않습니다.
- Windows에서 클로드코드가 Git Bash로 상태줄을 실행했다면 원래 명령도 bash로 실행합니다.
- `settings.json`을 읽을 수 없으면 상태줄은 건드리지 않고, 직접 등록할 명령을 안내합니다. 이 경우 세션 전송은 되지만 한도는 전송되지 않습니다.
- 래퍼 복사본은 연결할 때 플러그인 폴더에서 복사되고, 플러그인을 업데이트하면 **업데이트된 뒤 첫 훅이 실행될 때** 새 버전으로 자동 교체됩니다. 다시 연결할 필요가 없습니다. 옛 버전 플러그인으로 아직 돌고 있는 세션이 있어도 새 래퍼를 옛것으로 되돌리지 않습니다.

## 연결 해제

```
/c-monitor:connect --disconnect
```

이 명령은 두 가지를 합니다.

1. `statusLine`이 아직 플러그인 래퍼라면 원래 값으로 돌립니다(원래 없었으면 `statusLine` 항목을 지웁니다). 그 사이 사용자가 `statusLine`을 다른 명령으로 바꿔 두었다면 건드리지 않습니다.
2. 서버에 이 컴퓨터의 연결 해제를 알립니다(3초 제한). 서버는 기기 토큰을 막고, 대시보드에서 그 컴퓨터와 세션을 뺍니다. 웹에서 해제한 것과 같은 처리입니다.
3. 연결 설정 파일 `~/.c-monitor/config.json`(서버 주소와 기기 토큰)을 지웁니다. 그 뒤로 훅은 아무것도 보내지 않습니다.

```
✓ 상태줄을 원래대로 돌렸습니다.
✓ 연결을 끊었습니다(https://c-monitor.example.com). 이 컴퓨터의 세션은 더 이상 전송되지 않습니다.
```

서버가 꺼져 있는 등으로 알리지 못하면 이 컴퓨터 쪽 해제만 마치고 "! 서버에는 알리지 못했습니다. 웹의 설정 화면에서 이 컴퓨터를 해제해 주세요."라고 덧붙입니다. 그때는 웹 [설정의 "내 컴퓨터"](settings.md#내-컴퓨터)에서 "연결 해제"를 눌러 주세요. 웹에서 이미 해제된 컴퓨터라면 서버에 따로 알리지 않고 이 컴퓨터 쪽만 정리합니다.

큐·상태 파일·래퍼 복사본이 들어 있는 `~/.c-monitor/` 폴더의 나머지는 남으니, 완전히 지우려면 그 폴더를 지우면 됩니다.

플러그인까지 지우려면 연결을 먼저 해제한 뒤 실행합니다. 순서를 바꾸면 연결 해제 명령을 쓸 수 없게 되고, 상태줄은 `~/.c-monitor/bin/`의 래퍼 복사본을 가리킨 채 남아 한도를 계속 보냅니다. 그때는 `settings.json`의 `statusLine`을 직접 원래대로 고치고 `~/.c-monitor/` 폴더를 지워 주세요.

```
/plugin uninstall c-monitor@c-monitor
```

## 업데이트

터미널(클로드코드 밖)에서 마켓플레이스 정보를 새로 받은 뒤 플러그인을 업데이트합니다.

```
claude plugin marketplace update c-monitor
claude plugin update c-monitor@c-monitor
```

그다음 클로드코드를 다시 시작하거나, 실행 중인 세션마다 `/reload-plugins`를 실행합니다. **`/reload-plugins`를 하지 않은 세션은 옛 버전 훅으로 계속 돕니다.** 연결 설정은 그대로 남으므로 다시 연결할 필요는 없습니다. 대시보드의 컴퓨터 묶음과 설정의 "내 컴퓨터"에 나오는 플러그인 버전이 다음 전송부터 새 버전(지금은 0.3.1)으로 바뀝니다. 상태줄 래퍼 복사본도 이때 함께 새 버전으로 바뀝니다.

0.1.x에서 0.3.x로 올리면 원격 답장 훅(`PermissionRequest`, 글 받기)이 새로 걸립니다. 웹에서 답하려면 그 세션에서 `/reload-plugins`를 실행하거나 클로드코드를 다시 시작해야 합니다. 플러그인이 0.2.0보다 낮은 컴퓨터는 설정 화면에 "플러그인 업데이트 필요"가 붙습니다.

플러그인을 설치하기 전에 이미 시작된 세션에는 훅이 붙지 않아 대시보드에 올라오지 않습니다. 그 세션에서 `/reload-plugins`를 실행하면 훅이 붙어 그때부터 전송됩니다(첫 훅에서 그 세션의 대화 기록을 처음부터 읽어 보냅니다).

## 설정이 저장되는 위치

| 위치 | 내용 |
|---|---|
| `~/.c-monitor/config.json` | 서버 주소, 기기 토큰, 컴퓨터 ID와 이름, 플러그인 버전, 원래 상태줄 설정. 본인만 읽을 수 있게 만듭니다(Windows에서는 이 권한 값이 적용되지 않습니다) |
| `~/.c-monitor/pending.json` | 연결 명령의 `--start`와 `--wait` 사이에 진행 중인 연결 요청(기기 코드). 승인·거부·만료로 끝나면 지웁니다 |
| `~/.c-monitor/queue/` | 아직 못 보낸 묶음 |
| `~/.c-monitor/state/` | 세션별 대화 읽은 위치, 계정별 한도 마지막 전송 시각(`limits.json`), 세션별 컨텍스트·비용 마지막 전송 값(`stats.json`) |
| `~/.c-monitor/bin/statusline.mjs` | 상태줄 래퍼 복사본 |
| `~/.claude/settings.json` | `statusLine` 항목만 바꿉니다. 고치기 전 내용은 `settings.json.c-monitor.bak` |

환경변수 `C_MONITOR_HOME`을 주면 `~/.c-monitor` 대신 그 폴더를 씁니다. 클로드코드 설정 폴더는 `CLAUDE_CONFIG_DIR`를 따릅니다. 기기 토큰은 서버에는 해시로만 저장되고, 원문은 이 컴퓨터의 `config.json`에만 있습니다.
