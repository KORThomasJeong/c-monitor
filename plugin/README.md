# c-monitor — c-monitor 플러그인

클로드코드 세션의 상태·대화·5시간/주간 한도·세션별 컨텍스트 사용률과 비용을 c-monitor 서버로 보내는 플러그인입니다.
여러 컴퓨터에서 도는 세션을 대시보드 한 화면에서 볼 수 있고, 승인·질문·글로 웹에서 바로 답할 수 있습니다(원격 답장, 0.2.0부터).

## 설치

클로드코드 안에서 실행합니다.

```
/plugin marketplace add KORThomasJeong/c-monitor
/plugin install c-monitor@c-monitor
```

Node 18 이상이 필요합니다(`node` 명령이 PATH에 있어야 합니다). 다른 의존성은 없습니다.

## 연결

```
/c-monitor:connect https://c-monitor.example.com
```

1. 화면에 **링크**와 **확인 코드**(예: `K7QM-2XPA`)가 바로 나오고, 기본 브라우저가 그 링크로 자동으로 열립니다.
   원격 접속(SSH)처럼 화면이 없는 환경에서는 열지 않으니 링크를 직접 열어 주세요.
2. 구글로 로그인하고 코드를 확인한 뒤 승인합니다(10분 안에). 웹에서 거부하면 연결이 바로 취소됩니다.
3. 승인되면 이 컴퓨터가 등록되고, 그때부터 모든 세션이 자동으로 전송됩니다.

브라우저를 자동으로 열고 싶지 않으면 환경변수 `C_MONITOR_NO_OPEN=1`을 설정하세요.

터미널에서 직접 실행할 수도 있습니다(플러그인 폴더에서).

```
node bin/connect.mjs <서버주소>            # 요청하고 승인될 때까지 기다림
node bin/connect.mjs <서버주소> --start    # 요청하고 링크·코드만 출력한 뒤 바로 끝남
node bin/connect.mjs --wait                # --start로 시작한 요청의 승인을 기다려 연결을 마침
node bin/connect.mjs <서버주소> --no-open  # 브라우저를 자동으로 열지 않음
```

`/c-monitor:connect`는 `--start`와 `--wait`를 차례로 실행합니다. 클로드코드는 명령이 끝나야 출력을 보여 주기 때문에,
링크를 먼저 보여 주고 나서 승인을 기다리도록 두 단계로 나눠 두었습니다.

연결 상태 확인:

```
/c-monitor:connect
```

## 연결 해제

```
/c-monitor:connect --disconnect
```

서버에 알려 이 컴퓨터의 토큰을 폐기하고, 상태줄을 원래대로 돌린 뒤 연결 설정(토큰)을 지웁니다.
서버에 닿지 않으면 이 컴퓨터 쪽만 해제하고 알려 주니, 그때는 웹의 설정 화면에서 이 컴퓨터를 해제해 주세요. 플러그인까지 지우려면 `/plugin uninstall c-monitor@c-monitor`.
**플러그인을 지우기 전에 먼저 연결을 해제해 주세요.** 그래야 상태줄이 원래 명령으로 돌아갑니다.

## 무엇을 보내나요

| 종류 | 내용 |
|---|---|
| 훅 이벤트 | 세션 시작·종료, 질문 입력, 도구 실행 전후, 알림(승인 요청 등), 작업 끝남 |
| 대화 | 세션 대화 기록(transcript)을 훅마다 늘어난 만큼만 읽어 보냅니다. 사용자 글·어시스턴트 글·도구 입력과 결과 |
| 한도 | 상태줄 입력의 5시간·주간 사용률과 초기화 시각(계정별 60초에 한 번) |
| 컨텍스트·비용 | 상태줄 입력의 세션별 컨텍스트 사용률(%)과 누적 비용(USD, `cost.total_cost_usd`). 값이 바뀌었을 때만, 세션별 60초에 한 번(0.3.0부터) |
| 그 밖 | 클로드 계정 이메일, 작업 폴더, 깃 브랜치, 모델, 컴퓨터 이름·OS·플러그인 버전 |

**비밀 가림** — 보내기 전에 이 컴퓨터에서 API 키·토큰·`password=` 류를 `••••••••`로 바꿉니다
(`sk-…`, `ghp_…`, `AKIA…`, `xoxb-…`, `AIza…`, `GOCSPX-…`, `ya29.…`, JWT, `Bearer …`, 개인 키 블록 등). 가린 개수도 함께 보냅니다.
모양으로 찾는 방식이라 완벽하지는 않습니다. 대화에 민감한 내용을 적을 때는 이 점을 생각해 주세요.

## 원격 답장

웹 대시보드에서 이 컴퓨터의 세션에 답할 수 있습니다. 답할 수 있는 사람은 **그 세션의 주인 본인뿐**입니다.

| 웹에서 하는 일 | 세션에서 일어나는 일 |
|---|---|
| 승인 요청에 **허용 / 이 세션 동안 허용 / 거부** | 터미널의 승인 창에서 고른 것과 같습니다. 거부할 때 글을 함께 보내면 클로드가 그 글을 읽고 다르게 진행합니다 |
| 선택지 질문에 답 고르기·직접 쓰기 | 그 답으로 질문이 끝나고 작업이 이어집니다 |
| 글 보내기 | 세션이 작업을 끝내고 멈춰 있으면 그 글을 다음 요청으로 받아 다시 일합니다. 작업 중이면 끝난 뒤에 전달됩니다 |
| 원격 제어 열기 | 세션에서 `/remote-control`을 켜 두었으면 공식 화면(`claude.ai/code/…`)으로 가는 링크가 보입니다 |

**터미널이 항상 우선입니다.** 웹에서 답을 기다리는 동안에도 터미널의 승인 창·질문 창은 그대로 떠 있고, 먼저 답한 쪽이 적용됩니다.
서버가 꺼져 있거나 느리거나 무슨 문제가 있으면 플러그인은 아무것도 하지 않고 물러나므로 평소처럼 터미널에서 답하면 됩니다.

어떻게 동작하나요:

- **승인·질문** — 승인 창이 뜰 때 `PermissionRequest` 훅(`bin/ask.mjs`)이 서버에 요청을 등록하고(3초 안에 안 되면 포기), 웹에서 답이 올 때까지 서버에 되풀이해 묻습니다. 터미널에서 먼저 답하면 서버가 알려 주어 스스로 끝납니다.
  "이 세션 동안 허용"은 터미널의 "Yes, and …" 선택지와 같은 것으로, 그 세션에만 적용되고 설정 파일에는 남지 않습니다.
- **글** — 작업이 끝나거나 세션이 시작될 때 `Stop`·`SessionStart` 훅(`bin/inbox.mjs`)이 뒤에서 조용히 기다리다가, 웹에서 글이 오면 그 글을 세션에 넘겨 깨웁니다.
  세션마다 프로세스 하나가 떠 있으며(25초쯤에 한 번 서버에 물음), 클로드코드가 끝나면 같이 끝납니다.
- 승인 창이 뜨지 않는 권한 모드(자동 승인·승인 건너뛰기)에서는 승인 요청 자체가 없으므로 웹에도 나타나지 않습니다.

원격 답장 때문에 서버로 더 보내는 것:

| 언제 | 내용 |
|---|---|
| 승인 창이 뜰 때 | 세션 id, 도구 이름, 도구 입력(비밀을 가리고 큰 입력은 앞부분만), 서브에이전트 id, "이 세션 동안 허용"이 하는 일을 설명한 한 줄 |
| 선택지 질문이 뜰 때 | 위와 같고, 질문 글과 선택지(비밀 가림) |
| 훅 이벤트마다 | 원격 제어를 켠 세션이면 그 화면 주소 |

웹에서 보낸 글은 플러그인이 세션에 넘긴 뒤 서버에 **수신 확인**(세션 id와 글 id)을 보내고, 서버는 그때 글을 지웁니다(0.3.0부터).
수신 확인이 오지 않으면(넘기기 직전에 클로드코드가 끝난 경우 등) 서버가 잠시 뒤 같은 글을 다음 대기자에게 다시 줍니다.

**끄는 방법** — 웹의 **설정 → 컴퓨터**에서 그 컴퓨터의 **원격 답장** 스위치를 끕니다(기본은 켜짐).
끄면 그 컴퓨터의 세션에는 웹에서 답하거나 글을 보낼 수 없습니다. 세션 현황을 보는 기능은 그대로입니다.
스위치는 서버에 있으므로 플러그인은 끈 것을 미리 알지 못합니다. 승인 창이 뜨면 플러그인은 평소처럼 위 표의 내용으로 등록을 보내고,
서버는 그 내용을 **저장하지 않고** `disabled`로 답하며, 훅은 아무것도 출력하지 않고 바로 끝납니다(터미널에서 평소처럼 답하면 됩니다).
글을 기다리는 훅(`bin/inbox.mjs`)도 서버가 `gone`(기다릴 것 없음)으로 답하므로 바로 끝납니다.

## 클로드코드에 주는 영향

- 현황을 보내는 훅은 모두 비동기(`async: true`)라 클로드코드를 기다리게 하지 않고, 아무것도 출력하지 않습니다.
- 원격 답장의 승인 훅만 동기이지만 터미널의 승인 창과 함께 뜨므로 입력을 막지 않습니다. 웹에서 답이 왔을 때만 결정을 출력합니다.
- 서버가 꺼져 있으면 3초 안에 포기하고 디스크 큐(`~/.c-monitor/queue/`)에 남겼다가 다음 훅에서 순서대로 다시 보냅니다. 큐는 200묶음까지 두고 넘치면 오래된 것부터 버립니다.
- 웹의 설정 화면에서 이 컴퓨터를 해제하면, 플러그인은 다음 전송 때 이를 알아채고 큐를 비운 뒤 전송을 멈춥니다. `/c-monitor:connect`로 상태를 확인할 수 있고, 다시 연결하면 전송이 이어집니다.
- 서버가 컨텍스트·비용 필드를 모르는 옛 버전이라 거절(400)하면, 그 뒤 24시간은 컨텍스트·비용을 빼고 한도만 보냅니다. 상태줄 입력에 해당 필드가 없거나 모양이 달라도 상태줄 출력에는 영향이 없습니다.
- 연결하면 `~/.claude/settings.json`의 `statusLine`을 래퍼로 바꿉니다. 래퍼는 원래 상태줄 명령을 그대로 실행해 출력도 그대로 보여 줍니다(claude-hud 등 유지). 바꾸기 전 내용은 `settings.json.c-monitor.bak`으로 남깁니다.

## 파일 위치

| 위치 | 내용 |
|---|---|
| `~/.c-monitor/config.json` | 서버 주소, 기기 토큰, 컴퓨터 이름, 원래 상태줄 설정 |
| `~/.c-monitor/queue/` | 아직 못 보낸 묶음 |
| `~/.c-monitor/state/` | 세션별 대화 읽은 위치, 한도 마지막 전송 시각(`limits.json`), 세션별 컨텍스트·비용 마지막 전송 값(`stats.json`) |
| `~/.c-monitor/bin/statusline.mjs` | 상태줄 래퍼(복사본) |

환경변수 `C_MONITOR_HOME`으로 위치를 바꿀 수 있습니다. 클로드코드 설정 폴더는 `CLAUDE_CONFIG_DIR`를 따릅니다.

## 개발

저장소 루트에서:

```
npx vitest run --project plugin
```

테스트는 모두 임시 폴더에서 돌며 실제 `~/.claude`, `~/.c-monitor`를 건드리지 않습니다.

구조:

```
bin/hook.mjs        훅 진입점(이벤트 + 대화 증분 → 큐 → 전송)
bin/ask.mjs         원격 답장: 승인·질문 등록 → 웹의 답을 클로드코드에 돌려줌(PermissionRequest 훅)
bin/inbox.mjs       원격 답장: 웹에서 보낸 글을 기다렸다가 멈춘 세션을 깨우고 수신 확인(Stop·SessionStart 훅)
bin/connect.mjs     연결(--start / --wait)·상태·해제 명령
bin/statusline.mjs  상태줄 래퍼: 한도·컨텍스트·비용 전송(lib를 쓰지 않는 자급형 — 복사돼서 실행됨)
lib/config.mjs      저장 위치·설정 파일·진행 중인 연결 요청(pending.json)
lib/os.mjs          운영체제 표기(연결·훅·상태줄 래퍼가 같은 값을 보냄)
lib/wrapper.mjs     상태줄 래퍼 복사본 설치, 플러그인 업데이트 뒤 자동 교체
lib/browser.mjs     승인 링크를 기본 브라우저로 열기
lib/account.mjs     클로드 계정 이메일
lib/mask.mjs        비밀 가림
lib/transcript.mjs  대화 기록 증분 읽기
lib/queue.mjs       디스크 큐·묶음 나누기
lib/send.mjs        HTTP 전송
lib/toolinput.mjs   도구 입력 가리고 줄이기(훅 이벤트와 원격 답장이 같은 규칙)
lib/reply.mjs       원격 답장 본문 만들기, 웹의 답 → 훅 출력
lib/parent.mjs      클로드코드가 끝나면 기다리던 훅도 끝나게 하기
lib/stdin.mjs       훅 입력 읽기
```
